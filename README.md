# منصة منيو المحلات

موقع واحد وقاعدة بيانات واحدة تخدم كل محلاتك. كل محل له رابطه الخاص ومنيوه
وصاحبه، وصاحب المحل يدخل بإيميله ويعدّل منيوه هو فقط — بدون توكن ولا خطوة
نشر، والتعديل يوصل زبائنه فوراً.

```
منيو الزبون:      https://<موقعك>/?shop=alnakhla
لوحة التحكم:      نفس الرابط + ٥ ضغطات على اسم المحل، أو #admin
```

---

## ١) الإعداد — مرة واحدة فقط في حياتك

بعد هذي الخطوات، إضافة أي زبون جديد تاخذ دقيقة بدون أي شغل تقني.

### أنشئ مشروع Supabase

1. افتح <https://supabase.com> ← **New project** (اختر أقرب منطقة).
2. احفظ **Database Password** عندك.

### جهّز الجداول

من **SQL Editor** ← **New query**: الصق محتوى
[`supabase-setup.sql`](supabase-setup.sql) كامل ← **Run**.

ينشئ جدول المحلات ومخزن الصور وسياسات الصلاحيات:
الزبائن يقرؤون فقط، وصاحب المحل يكتب في محله فقط، وأنت تدير الكل.

### أنشئ حسابك وعيّن نفسك مدير منصة

1. **Authentication ← Users ← Add user**: إيميلك وكلمة مرور، وفعّل
   **Auto Confirm User**.
2. ارجع لـ **SQL Editor** وشغّل آخر سطرين في ملف الإعداد بعد ما تبدّل الإيميل
   بإيميلك:

```sql
insert into public.platform_admins (user_id, email)
select id, email from auth.users where lower(email) = lower('YOUR@EMAIL.COM')
on conflict (user_id) do nothing;
```

### أوقف التسجيل الذاتي

**Authentication ← Sign In / Providers** ← أوقف **Allow new users to sign up**،
حتى ما ينشئ أحد حساباً من نفسه.

### اربط الموقع

من **Project Settings ← API** انسخ **Project URL** و **anon public key**،
وحطهما في [`assets/js/config.js`](assets/js/config.js).

> القيمتان عامّتان بطبيعتهما وتنشحن مع أي موقع يستخدم Supabase؛ الحماية تجي من
> سياسات الصلاحيات. **لا تضع أبداً مفتاح `service_role`.**

---

## ٢) إضافة زبون جديد (دقيقة)

1. **Supabase ← Authentication ← Users ← Add user**: إيميل صاحب المحل وكلمة
   مرور مؤقتة، مع **Auto Confirm User**.
2. افتح موقعك ← لوحة التحكم ← تبويب **المحلات** ← **+ إضافة محل**:
   اسم المحل، ورابطه بالإنجليزي (`alnakhla`)، وإيميل صاحبه.
3. اضغط **نسخ الرابط** وأرسله له مع بيانات دخوله.

خلاص. المحل يبدأ بمنيو جاهز يعدّله صاحبه كما يشاء.

---

## ٣) الأدوار

| | مدير المنصة (أنت) | صاحب المحل |
|---|---|---|
| يشوف تبويب «المحلات» | ✅ | ❌ |
| يضيف ويحذف ويوقف محلات | ✅ | ❌ |
| يعدّل منيو أي محل | ✅ | محله فقط |
| يغيّر رابط المحل أو مالكه | ✅ | ❌ (محمي في قاعدة البيانات) |

صاحب المحل لو فتح رابط محل غيره وحاول يعدّل، قاعدة البيانات ترفض ويظهر له
تنبيه، ويرجع المنيو لحالته — جرّبناها.

---

## ٤) لوحة التحكم

الدخول: **٥ ضغطات على اسم المحل** أو `#admin` في آخر الرابط، ثم الإيميل
وكلمة المرور. الجلسة تبقى مفتوحة فما تحتاج تسجّل دخول كل مرة.

| التبويب | الوظيفة |
|---|---|
| **المحلات** | (لك أنت) إضافة محل، نسخ رابطه، إيقافه، حذفه، وفتح منيو أي محل للتعديل |
| **الأصناف** | إضافة / تعديل / حذف / ترتيب / إخفاء، السعر والسعرات والوصف والصورة، وسعر «قبل الخصم» يدخل الصنف تلقائياً في قسم العروض |
| **الأقسام** | إضافة وتعديل وحذف وترتيب أقسام المنيو |
| **معلومات المحل** | الاسم، الشعار، العملة، الألوان، بيانات التواصل، وتغيير كلمة مرور الدخول |
| **الحالة والنسخ الاحتياطي** | حالة الاتصال، وتنزيل نسخة احتياطية واسترجاعها |

**الصور:** اختر صورة من الجهاز داخل نموذج الصنف — تتصغّر إلى 800 بكسل وتنرفع
لمجلد المحل، ثم اضغط **حفظ**.

**لو انقطع الاتصال:** يظهر تنبيه أحمر في تبويب الحالة ويُعرض آخر منيو محفوظ.
لا تعدّل وقتها — أي حفظ يفشل يرجّع التعديل لحالته ويخبرك، فما فيه تعديل
يضيع بصمت.

## ٥) التشغيل محلياً

```bash
python3 -m http.server 8000
```
ثم <http://localhost:8000/?shop=SLUG>

النشر مجاناً على GitHub Pages: **Settings → Pages → Deploy from a branch →
`main` → `/ (root)`**. ولو ربطت دومين خاص، تصير روابط زبائنك
`menu-example.com/?shop=alnakhla`.

## ٦) ملاحظات أمان

- الدخول بحساب حقيقي تديره Supabase، والصلاحيات مطبّقة داخل قاعدة البيانات —
  يعني حتى لو قرأ أحد كود الموقع كامل ما يقدر يعدّل منيو مو له.
- إخفاء اللوحة (٥ ضغطات) للراحة فقط، وليس حماية.
- أوقف التسجيل الذاتي، واستخدم كلمات مرور قوية.
- `service_role` لا يُوضع في الموقع أبداً.
